# Інструкції для AI-агента

Репозиторій з автотестами: UI (saucedemo.com) і API (restful-booker) на Playwright + TypeScript.

## Стек і структура
- `@playwright/test`, TypeScript у `strict`-режимі. Жодних інших тест-раннерів і бібліотек без запиту.
- UI: `tests/ui/` — Page Object у `tests/ui/pages/`, фікстури в `tests/ui/fixtures.ts`.
- API: `tests/api/` — усі HTTP-виклики лише через `BookingClient` (`bookingClient.ts`), не через сирі `request.*` у тестах.
- Проєкти Playwright: `ui` і `api` (див. `playwright.config.ts`).

## Правила написання тестів
1. **Локатори**: тільки `getByTestId` (атрибут `data-test`, налаштовано в конфігу) або `getByRole`. Без CSS-класів, XPath і `nth()` там, де є стабільний атрибут.
2. **Жодних `waitForTimeout` / sleep.** Лише web-first assertions (`await expect(locator).toHave...`).
3. **Не хардкодь очікувані дані, які можна взяти зі сторінки** (ціни, кількість товарів у кошику тощо). Хардкод дозволений для текстів помилок і для кількості товарів у каталогу (6).
4. Кожен тест незалежний: сам логіниться через фікстуру `loggedIn`, сам створює свої дані в API, прибирає за собою.
5. Не використовуй `test.describe.serial` — залежні кроки оформлюй як один тест з `test.step`.
6. Знайдений баг **не маскуй** зміною очікування під фактичну поведінку. Пиши тест з правильним очікуванням + `test.fail(true, 'BUG-XXX: ...')` і додай баг-репорт у README.
7. Назви тестів — українською, описують поведінку, а не реалізацію.
8. Секрети не потрібні: облікові дані обох сервісів публічні, але читаються з env з дефолтом.

## Перевірка перед тим, як сказати «готово»
- `npm run typecheck` — без помилок.
- `npx playwright test` — зелений; якщо щось падає, розберись у причині (trace у `test-results/`), а не додавай ретраї чи таймаути.
- Не вигадуй селектори: якщо не бачив DOM, скажи про це прямо.
